# RAG 调用方式：智能调用以工具化检索实现，强制调用保持模型前预注入

Agent 的知识库检索时机此前是固定的——开启知识库即每次运行前必检索一次并把结果注入系统提示（强制）。新增 `rag_call_mode` 后需要区分「每次必检索」与「由 LLM 自主判断是否检索」，而这两种语义对应完全不同的机制：强制是运行时确定性的前置步骤，智能则必须是模型可自主发起的工具调用。我们决定：智能调用走工具化检索（注册 `rag_search` 工具、把可用知识库列表写进系统提示，由模型决定是否调用、调用哪个库、调用几次），强制调用保持既有的模型前预注入；`rag_call_mode` 仅在 `ragEnabled` 开启时生效，迁移与快照缺省值取 2（强制）以兼容存量 Agent。当绑定模型不支持 function calling 时，智能调用回退为强制调用并告警。

**Status**: accepted

**Considered Options**:
- 两次模型调用（先让模型判断是否需要检索，再带上下文回答）：多一次模型往返，成本与延迟翻倍，判定质量也未必优于工具调用 —— 否决。
- 统一走工具化（强制也改成工具）：破坏存量「开启即检索」的确定性语义与既有的「模型前 `RETRIEVAL`」事件顺序 —— 否决。
- 保留强制预注入 + 新增智能工具路径（本方案）：两种语义各自贴合其机制，存量行为零变化 —— 采纳。

**Consequences**:
- `v5ai_agent` 表与 Agent 快照 JSON 新增 `ragCallMode`；未重新发布的存量 Agent 缺省按强制调用解析。
- 智能调用的检索命中以 `rag_search` 工具事件（`TOOL_CALL` → `TOOL_RESULT`）原生呈现，并随后追加 `RETRIEVAL`；与强制调用「模型前 `RETRIEVAL`」的事件顺序不同。
- 智能调用依赖模型的 function calling 能力；运行期经 `ModelToolSupportResolver` 判定，不支持则回退强制调用并记录告警日志。
- 可用知识库列表仅在智能调用的系统提示中注入；强制调用不注入列表。
