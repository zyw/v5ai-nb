# 迁移历史冻结，schema 全貌单独成文

`db/migration/` 攒到 43 个迁移文件时，「文件太多」成了真实痛点，而更深的痛点是：**想读懂当前 schema 必须把这 43 个文件按顺序在脑子里 replay 一遍**——V8 把 `v5ai_application*` 改名成 `v5ai_agent*`、V19 把日志表改名成 `plm_*`、V22 又把 V7 建的 `v5ai_tenant` 删掉，光看 `CREATE TABLE` 拼不出今天的表。同时注释是「谁顺手谁加」的状态：43 张表 420 列里 197 列有注释，`plm_*` 那批 100% 有，而 `v5ai_*` 的核心表（mcp/skill/run/workflow）几乎为空——半有半无比全无更糟，读者分不清「没注释」是无需说明还是漏了。我们决定：**不碰历史**（V1–V41 冻结，只增不改），**新增 V43 补齐注释、V44 删掉一张遗留死表**，并**另出一份从重放库导出的 schema 全貌** `docs/db/schema.md`；`db/migration/README.md` 提供逐版本索引，取代「压平目录」这个动作。

**Status**: accepted

**Considered Options**:
- **压平成单个 baseline**（把 V1–V41 合成一个 `V1__baseline.sql`，靠 `baseline-on-migrate` + 手工 `repair`）：文件数从 43 降到 1，最彻底。否决——Flyway 默认校验 checksum，唯一那个库（`v5ai_nb`，全部存量数据所在）已应用全部 40 条记录；改历史要么让库重建、要么做一次带风险的手工 repair，而收益只是目录观感。
- **把历史移入 `archive/` 子目录**：已核实 Flyway 的 locations 是**递归扫描**的，移动文件不改 checksum、不改版本序，主目录只剩新迁移、观感立刻清爽。本轮未采纳——纯外观收益，不抵「多一层目录」的认知成本；改为用 README 索引解决同一问题。
- **全貌文件从现网库导出**：省一步重放。否决——现网是**已部署状态**，会落后于迁移头（当时 V42 已提交未部署，导出的文件落地就少两列）。
- **全貌文件手工维护**：否决——没有生成路径的 schema 文档必然腐烂，半年后又多一份不可信的真相。
- **全貌文件从「重放后的临时库」导出**（本方案）：采纳。把 V1–V44 完整重放到一个一次性库，它天然就是「迁移头」的样子；重放本身还顺带验证了「新环境能不能从零建出同样的 schema」。
- **给注释迁移搭上顺手要做的 DDL**：否决——一个纯 `COMMENT ON` 的迁移可以被无脑信任、可以被任何人 review、出错概率接近零；一旦混进 DDL，它立刻升级成需要架构评审、且要在有真实数据的库上执行的改动。死表清理因此单列 V44。

**Consequences**:
- **V1–V41 冻结**（2026-09-19），后续按 V42、V43… 递增；`db/migration/README.md` 是逐版本索引，`docs/db/schema.md` 是迁移头的全貌快照。
- **改号规则**：迁移文件在**从未被任何库应用过**之前改号是安全的；一旦某个库应用了它（`v5ai_flyway_schema_history` 落了记录），改名就会 checksum mismatch，只能顺延新号。本项目只有那一个库、迁移只随应用启动执行，所以「合并前改名」零成本。
- **`docs/db/schema.md` 会滞后**：它没有自动同步机制，靠约定——新增迁移后按 `docs/db/dump-schema.sql` 重跑。这是明知取舍：给它加硬性同步约定只会制造新的漂移借口，而文件头已写明生成时间与来源。
- **重放验证的结论**：V1–V44 从零在 PostgreSQL 17.11 上一次跑通，与现网库逐列比对**零计划外差异**——差异恰好是 V44 删掉的那张表与 V43 补的那 221 个列注释/29 个表注释。也就是说历史迁移**确实能重建出现网 schema**，此前「历史一定漂移」的担心不成立。
- **V43 里 `daily_tokens` 照实写明「当前未参与拦截」**：`checkAllowed` 只校验每分钟限流与每日调用次数。把「配了不生效」钉在 schema 上，比写一句漂亮但误导的注释更符合本仓库「把真话写进迁移注释」的既有风格（参见 V42 对 `metadata` 的处理）。
- **V44 删表与删清理代码必须同一个提交**：只删表会在级联删除时报 `relation "v5ai_agent_model" does not exist`，只删代码则留下「表还在但没人管」。
